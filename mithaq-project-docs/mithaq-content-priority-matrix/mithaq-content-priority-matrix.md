---

## 1. Executive Summary

This document defines Mithaq's content hierarchy for the full 10-scene landing experience before visual design, final copywriting, localization, or frontend implementation begins.

The matrix answers:

- What each scene must communicate in one sentence.
- What the user must understand if 3D does not render.
- Which CTA belongs in each scene.
- Which secondary copy supports the scene.
- Which enrichment is optional and content-dependent.
- Which content is required for accessibility and static fallback.
- Which content remains pending final confirmation.
- Which claims, proof points, workshop details, and mentor details must not be invented.

Content priority position:

**Each scene should have one dominant DOM-first message. The 3D layer may make the message memorable, but the page must still communicate the Mithaq journey, workshop offer, trust structure, FAQ, and conversion paths through accessible text if canvas, motion, or assets fail.**

Status is **PASS WITH CONDITIONS** because final content still depends on Phase 6 copywriting, final Arabic localization, final workshop/mentor/proof details, WhatsApp number, privacy/legal wording, and stakeholder approval.

This is content hierarchy planning only. It is not a final website copy deck, Arabic translation, SEO copy, FAQ copy, UI design, or implementation task.

## 3. Content Priority Principles

| Principle | Meaning |
| --- | --- |
| One scene, one dominant message | Each scene must communicate one clear idea. |
| DOM-first content | All critical content must exist outside canvas. |
| 3D supports, never replaces | 3D can enrich meaning but cannot carry the only meaning. |
| CTA must match intent | The action should match the user's stage in the journey. |
| No fake proof | Proof/trust content must be verified before use. |
| No fake urgency | No countdowns, fake seats, fake deadlines, or unsupported scarcity. |
| Bilingual parity | Arabic and English must carry equivalent meaning. |
| Mobile clarity | Mobile content should be shorter and clearer. |
| Accessibility clarity | Screen reader users must understand the same hierarchy. |
| Portfolio, not LMS | Content must not sound like a dashboard/course platform. |
| Placeholder-safe | Unknown workshop/mentor/proof content must be clearly marked pending. |

## 4. Priority Definitions

### P0 - Essential Content

Must appear in DOM and static fallback.

Includes:

- Primary message.
- Primary scene heading direction.
- Core explanatory sentence.
- Main CTA where relevant.
- Route/scene purpose.
- Accessibility equivalent.

### P1 - Supporting Content

Should appear if space and design allow.

Includes:

- Secondary explanation.
- Supporting bullets.
- Short proof note if verified.
- Secondary CTA.
- Small guidance text.

### P2 - Optional Enrichment

Can appear only if final content, layout, and performance allow.

Includes:

- Visual metaphor explanation.
- Optional quote.
- Optional microcopy.
- Optional interaction note.
- Optional stat if verified.
- Optional storytelling detail.

### Blocked / Pending

Cannot be used until verified.

Includes:

- Instructor credentials.
- Testimonials.
- Participant numbers.
- Capacity/seat count.
- Pricing.
- Workshop dates.
- Certificates.
- Institutional partners.
- WhatsApp number.
- Final legal/privacy wording.

## 9. Bilingual / RTL Content Notes

Rules:

- Arabic and English must carry equivalent meaning, not literal word-for-word translation.
- Arabic should feel authoritative but not overly formal.
- English should feel premium and clear, not SaaS-like.
- Arabic headings may require more space and line-height.
- English headings may be shorter but must not dominate layout decisions.
- CTA labels must be tested at 320px mobile width.
- Do not mix Arabic and English in one animated line.
- Do not bake Arabic or English text into 3D textures.
- Tajawal 700 is the safe Arabic display default.
- Lemonada is accent-only pending review.
- Final localization belongs to P6.03.

| Scene | Arabic Content Risk | English Content Risk | Priority Decision |
| --- | --- | --- | --- |
| 01 | Overly poetic covenant language may become unclear. | Too much cinematic mystery may delay meaning. | Keep brand anchor short and direct. |
| 02 | Long Arabic hero line may wrap heavily. | English may sound SaaS-like if too functional. | Localize hero separately with equivalent meaning. |
| 03 | Problem language may sound accusatory. | Problem language may sound too negative. | Frame gap respectfully. |
| 04 | Method terminology may become abstract. | Method copy may become jargon-heavy. | Use practical verbs and short principles. |
| 05 | Pillar labels may need localized names, not literal labels. | Pillars may sound generic. | Give each pillar a practical meaning. |
| 06 | Workshop titles/CTAs may overflow. | Cards may sound like a catalog. | Keep cards concise and dossier-like. |
| 07 | Titles/credentials may be culturally sensitive. | Credentials may feel inflated if vague. | Use only verified role language. |
| 08 | Proof language may overclaim. | Proof blocks may feel empty without facts. | Use verified proof or honest methodology. |
| 09 | FAQ answers may become long. | FAQ may become too terse. | Prioritize clarity and fit questions. |
| 10 | CTA may sound too forceful if translated literally. | CTA may sound too salesy. | Use low-pressure action language. |
